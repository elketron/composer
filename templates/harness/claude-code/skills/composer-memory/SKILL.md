# Composer memory

Long-lived knowledge lives in `site://memory`:

- `site://memory/user`: who the user is and how they like to work.
- `site://memory/projects/<name>`: facts about a project that aren't in its code.
- `site://memory/topics/<name>`: anything else worth keeping.
- `site://memory/feedback/<name>`: corrections and confirmed ways of working.

Open `site://memory` first; its index describes the page format. Read the pages relevant to your
ticket before you start. Only write memory when you learned something durable that isn't in the
code or the ticket, and keep each page to one subject. Prefer `edit` over `write` so you don't drop
what is there.
