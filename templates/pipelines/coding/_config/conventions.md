# Conventions

How code is written in the projects this pipeline works on. A project's own rules (its `CLAUDE.md`,
`CONTRIBUTING.md`, the code around the change) win over these.

- Match the surrounding code: naming, comment density, idiom.
- Small, reviewable changes; one concern per commit.
- Tests next to the change; run the project's checks before finishing.
- No new dependencies without saying why in the plan.
