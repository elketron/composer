The project hub — sites operate on a project

A project is a folder and a page. A site is a capability that operates on it. A work is one instance of a site on a project. The project page is the hub; inside every work, project/ is the same project for the agent and the app.

01The shape

One project, three sites. Each site has its own works. The project page lists the sites; a site can be used on many projects; a work is the instance that ties one site to one project.

02A work: project/ is the project

The work folder is the paper trail. project/ is a view of the real folder: a symlink. The mode picks the target — the project root, or the ticket's worktree.

03The worktree / diff flow

This is the review loop. The agent and the app see the same worktree: the app's file tree and its diff are the same branch. That is what makes review before approval possible.

04Local vs work: the worktree source

The app and the agent never care where the worktree came from. ticket_worktree is the source; project/ is the path they use.

05Agent ↔ app parity

Same work, same paths, same mode. The app is not a second story about the project.

Without a work, the app's projectFile(path) is the project's main folder (the app's own assets). With a work, it follows the work's project/, so review sees the worktree.

06The three modes

The site gives the default; the work or the stage can override it.

read · default

project/ → project root

Reads the project. A write through project/ is refused with the reason.

write

project/ → project root

Writes the project in place: video renders, 3D assets, design outputs.

worktree

project/ → ticket worktree

Writes code on ticket/<id>; review the diff; merge lands the branch.

07The project page is the hub

The page is the data; the projects site's app is the hub.

# site://projects/A.md
type: project
root: ~/Projects/A
sites: [coding, video, 3d]
tags: [game]
status: active

# body: what it is, decisions, state

The hub's project.overview:

project A

├── sites
│   ├── coding   works: save-system, inventory
│   ├── video    works: trailer
│   └── 3d       works: crashed-ship
├── branches  ticket/… waiting to merge
├── memory    the page body
└── switches  harness, tool rules

new_project writes site://projects/<name>.md, registers it in the projects index, and claims the folder. Old site://memory/projects/<name>.md pages are read as a fallback.
