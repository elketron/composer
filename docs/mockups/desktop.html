composer app: the desktop layout

The phone got its second round (app.html); the wide layout still shows the first one, and the features since (merging tickets, Claude Code workers and their approvals, attachments) were built phone-first. Same theme and components; what changes is the frame around them and what a big screen can show at once.

What gets in the way on a wide screen today
  • It opens on the server page. Model, slots, version and site chips, then a second copy of the session list. The rail's own session list is a flat tree of every worker ever run.
  • Nothing says what needs you. The phone has Needs you / Running / Recent; the rail doesn't, and approvals only show as a bar over the page.
  • The chat has no menu. Project, compact, turning Claude Code off and "Review changes" are phone-only (⋮ in the phone's chat header).
  • Review is a full-screen page. On a desktop it covers the chat you came from; there is room to show it beside the chat, like the reader.
  • The reader always takes half the width and is the only thing that can sit beside the chat; a worker's changes, the ticket and the orchestrator can't.
  • Following a worker means switching away from its orchestrator; there is no way to keep both in view.
  • Keyboard: ctrl-enter sends and ctrl-1…9 switches servers; nothing else. No palette, no quick switch between sessions.
  • Pairing and server settings are phone screens stretched to the window.
The frame

Four columns: the server rail, the session list (the phone's Chats tab), the chat, and a side pane with tabs: Page (the reader), Changes (a ticket's review, or the project's diff), Worker (another session, live). The side pane is resizable and closes with esc; under 1100px it overlays the chat instead of sitting beside it. A site's micro app opens in its own App tab, so it can sit beside the chat while you talk about it. The session list collapses (ctrl b, or its ‹ button) to a narrow strip of session dots, giving the chat and the side pane its width.

Not in this round
  • Editing pages in the reader (the TUI's e): later, with a proper editor.
  • Showing and removing tool rules one by one: the count is shown; editing them stays in state/tool_rules.json for now.
  • Several windows (a chat per window): the side pane's Worker tab covers the common case.
